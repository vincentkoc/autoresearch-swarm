# R2 artifact bytes

The native R2 byte adapter implements the existing `BlobStore` contract. The
native database remains responsible for access, quota, publication, retention,
reader pins and research evidence. This adapter does not move research authority
into a Cloudflare Worker.

Storage selection is persisted in the native runtime identity. Filesystem storage
remains the default. R2 requires the optional `s3` extra and explicitly named
credential sources. Existing SDK, HTTP, CLI and stdio MCP commands use the same
artifact service after initialization; they do not need R2-specific operations.

## Initialization

Install the optional dependency with `uv sync --extra s3`. Create a non-secret
`storage.json` file:

```json
{
  "kind": "r2",
  "endpoint": "https://ACCOUNT_ID.r2.cloudflarestorage.com",
  "bucket": "research-artifacts",
  "prefix": "research",
  "max_object_bytes": 1073741824,
  "access_key_env": "R2_ACCESS_KEY_ID",
  "secret_key_env": "R2_SECRET_ACCESS_KEY"
}
```

Replace the endpoint with the lowercase account endpoint. Supply the two named
credential environment variables through your usual private secret mechanism,
then initialize:

```sh
research --state-dir ./state init --storage-config storage.json
research --state-dir ./state serve
```

For Python initialization, pass `storage_config=R2Config(...)` to
`LocalRuntime.open(Path("./state"))`. Thereafter `ResearchClient.local(Path("./state"))`
reopens that pinned selection. `research init` with the identical configuration
is idempotent. A different backend, endpoint, bucket, prefix, object limit or
credential-source name is refused, including in an empty initialized runtime.
Credential values may rotate within the same named sources. Migrating a live
store requires a separate explicit migration; this release does not implement it.
Existing runtime identities without a storage field retain filesystem behavior.

The runtime creates `r2-staging` with its complete binding before publishing the
runtime identity. If initialization stops before identity publication, orphan
staging requires explicit recovery. Once an identity exists, reopening can only
validate and reuse its staging, including during partially completed bootstrap.
Missing staging or binding never triggers automatic recreation. SDK/credential
preflight precedes new state creation.

## Configuration and staging

`R2Config` freezes the HTTPS R2 account endpoint, bucket, key prefix, per-object
limit and two environment-variable names for credentials. It stores no credential
values and does not fall back to ambient AWS credentials. The S3 transport uses
the `auto` region, path addressing, verified TLS, bounded connection/read timeouts,
no ambient proxy and one SDK attempt. Recovery repeats the original operation.

The current adapter supports single PUT objects up to 5 GiB. Multipart upload is
not implemented. `ArtifactService(max_object_bytes=...)` must receive the configured
limit so an oversized upload is rejected before quota reservation or durable
upload admission. Aggregate capacity remains `storage_limit_bytes`. The adapter
also checks direct byte-operation calls independently.

`R2StagingBinding` pins the workspace, controller, staging UUID and configuration
digest. `R2BlobStore.initialize` creates a new private staging directory explicitly;
the ordinary constructor only opens a matching existing binding. A changed
destination, missing directory or incomplete staging requires recovery. Opening
the adapter does not substitute a new store.

Staging contains immutable upload descriptions, permanent generation-retirement
records, resumable local bytes and native locks. It is recovery state, not a
disposable cache. All native controller processes for this authority must share
the same qualified staging/lock directory on one host. Temporary verified reader
copies are removed when their reader closes. Successfully published local payload
bytes are removed after full remote verification; generation metadata remains.

## Publication and reads

Each upload has its own remote key:

```text
<prefix>/<workspace UUID>/<content SHA-256>/<upload UUID>
```

The upload UUID is the storage generation. A content digest, ETag or opaque
provider object version does not replace it. Upload parts retain the filesystem
adapter's offset, overlap, digest and fsync behavior before cloud publication.

Payload publication uses conditional `PutObject` with `If-None-Match: *`. A
successful or already-existing generation is read back and checked against its
metadata, exact length and full SHA-256 before the adapter returns a `StoredBlob`.
A lost PUT reply leaves its local bytes and native quota reservation available for
recovery. Reopening and retrying uses the same generation.

R2 documents that conditional PUTs are evaluated atomically against committed
bucket state. This is the provider guarantee required by the adapter.
[R2 S3 API](https://developers.cloudflare.com/r2/api/s3/api/)

A reader downloads into a private temporary file, verifies the complete object,
rewinds it and only then yields bytes to its caller. Missing, corrupt, oversized
or retired objects fail before the caller reads any data. ArtifactService keeps
the catalog pin around the reader lifetime. Fetch creates its destination
exclusively and removes only its own partial output after failure.

## Deletion and delayed writes

A negative HEAD/GET or successful DELETE cannot prove that an earlier timed-out
PUT will never complete. Releasing quota on that basis could permit a late write
to resurrect unaccounted bytes. R2's strong consistency covers committed state;
it does not turn a negative read into cancellation of an outstanding operation.
[R2 consistency model](https://developers.cloudflare.com/r2/reference/consistency/)

Deletion first persists the generation's retirement locally. It then overwrites
that exact remote key with a zero-byte retirement marker and verifies that marker
through a positive read. Every payload PUT requires the key to be absent, so a
delayed payload cannot overwrite the committed retirement marker. Empty payloads
remain distinct because their metadata identifies them as payloads.

Retirement markers are permanent. Do not apply expiration or external deletion
to them. The adapter reclaims payload bytes while retaining fencing metadata;
provider metadata/request costs remain. A later generation of identical content
has a different key, so cleanup of the old generation cannot remove the new one.

The existing catalog keeps deleting/aborting bytes charged until this positive
fence is confirmed. Timeout or failure keeps the reservation. A repeated cleanup
can confirm an already-written marker and finish the original lifecycle.

## Evidence level

`tests/storage/test_r2_storage.py` uses a deterministic conditional-object simulator for
lost replies, delayed writes, positive retirement, corruption, independent-store
concurrency, deduplication, native pins and quota. `tests/storage/test_r2_transport.py`
checks exact requests against the optional boto3/botocore SDK, including conditional
headers, stream closure and sanitized failures. `tests/storage/test_r2_runtime.py` covers persistent selection, concurrent initialization,
legacy identities, partial-bootstrap failures and missing staging.

`tests/adapters/cloudflare/test_cloudflare_r2.py` runs the native runtime and SDK against an actual
local Wrangler/workerd R2 binding. It verifies publication across emulator restart,
reader pins, deduplication, corruption refusal, uncertain deletion accounting and
a delayed conditional write losing against a retirement marker. Its loopback
fixture bridge is test-only; it is not the production S3 transport.

Run that qualification with `RESEARCH_CLOUDFLARE_TESTS=1 uv run pytest -q
tests/adapters/cloudflare/test_cloudflare_r2.py` on a supported native POSIX host with Node available.
It owns only its fixture process group. The pinned R2 binding API is documented
by [Cloudflare](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/).
Neither the emulator nor SDK stubs establish hosted authentication, network
recovery, throughput or production S3-to-R2 interoperability.
