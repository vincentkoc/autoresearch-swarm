# Campaign artifact storage

The campaign CLI stores artifact bytes in a local directory beside the selected
SQLite database. For `.research/program.sqlite`, the directory is
`.research/program.sqlite.files`. Keep the database and its files together.

## Upload and download

With the project environment active, upload an existing result file. The JSON
response includes its `id`, SHA-256 digest and byte count.

~~~sh
research artifact upload result.json --db .research/program.sqlite
~~~

Use the returned `id` in place of `ARTIFACT_ID` and choose a new destination path.

~~~sh
research artifact download ARTIFACT_ID restored.json --db .research/program.sqlite
~~~

## R2 adapter and historical runtime

The package also includes a Python R2 byte adapter. Its simulator exercises
generation recovery and content verification. Its transport tests check
conditional requests against an SDK stub. Hosted authentication, throughput and
provider interoperability require separate measurements. [Adapter](../src/research_swarm/storage/r2.py) · [Simulator tests](../tests/storage/test_r2_storage.py) · [Transport tests](../tests/storage/test_r2_transport.py)

The earlier controller selected R2 during runtime initialization. Its runtime
tests covered persistent selection, concurrent initialization, partial bootstrap
and missing staging. For records from that controller, the versioned guide
preserves the configuration, generation retirement and original qualification
evidence.
